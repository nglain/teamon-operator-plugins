# TeamON — каталог плагинов

Выпуск 2026-09-18: **Operator 0.2.17**, **Installer 0.1.6**.
Master **1.0.104** развёрнут: новый вход остаётся на HTTPS и переживает
перезапуск MCP без локального callback. Пакеты проверены в отдельном чистом
профиле; подтверждение человеком входа и работы своей компании — отдельный тест.

Наш Git-каталог для Codex. Здесь только готовые пакеты и их зависимости:
без паролей, личных входов, настроек и переписок компаний.

## Установка из одного файла

Обычному пользователю передайте [один установочный файл](teamon-operator-install.md).
Он прикладывает его в Codex и пишет **«Установи по файлу и проведи до входа и пульта»**.
Агент устанавливает Operator напрямую, показывает подтверждённые этапы текстом,
а после установки просит в новой задаче выбрать настоящий @TeamON Operator.
Затем человек отправляет самодостаточный запрос на проверку входа и открытия пульта.
Команды ниже — справка для ручной установки, не обязательные действия получателя.

Нужны Codex с плагинами, Git и Node `>=24.14.1 <25` в PATH приложения.
Переход с установленного пакета проверен в macOS Codex. Windows пока не принят.

```sh
codex plugin marketplace add https://github.com/nglain/teamon-operator-plugins.git
codex plugin add teamon-operator@teamon-operator
```

Если наш каталог уже подключён на main, вместо первой команды:

```sh
codex plugin marketplace upgrade teamon-operator
```

Не подменяйте каталог с другим источником или закреплённым ref автоматически.
GitHub-аккаунт для чтения этого публичного каталога не требуется.

1. Установка Operator напрямую из официального каталога и текстовая проверка этапов.
2. В новой задаче выберите **@TeamON Operator** из меню упоминаний.
3. Проверка входа → браузерная авторизация при необходимости → HTML-пульт →
   компания → проверка доступа → короткий гайд.

Без MCP Apps, Visualize, кнопок установки, процентов и анимации. Если хост не
поддерживает черновик, используется явный ручной выбор плагина через @.
После отправки проверяются реальные инструменты; плашка сама по себе их не гарантирует.
Установка не означает вход. После подтверждённого входа `workspace_open` открывает HTML-пульт:
компании → агенты → пользователи и обращения. Обсуждение и действия остаются в чате.
Это не админка Master. При отдельном запросе входа в компанию подтвердите его
в браузере; пароли и коды не нужно присылать в чат.
Пароли вводятся только на защищённой странице входа. Доступы назначает администратор.

Уже есть Installer из `personal`? Для перехода согласуйте один источник и отключите
старый helper, чтобы не подключать два одинаковых MCP. Личные настройки не удаляйте.

## Что поставляется

- **TeamON Operator 0.2.17** — MCP с HTML-пультом, runtime-диагностикой и прямым onboarding.
- **TeamON Installer 0.1.6** — legacy-посредник для старых профилей; новый установочный
  файл его не вызывает и не требует.

Инвентарь Installer: `plugins/teamon-installer/distribution.json`.
Инвентарь Operator: `distribution.json`; он покрывает только файлы Operator,
а не общий изменяемый каталог. Встроенных данных компаний в пульте нет.
Релизные пакеты не содержат private Git history. Source Git и публикация пакета
— разные операции; после обновления каталога установленный runtime проверяется отдельно.

## Чего эта публикация не доказывает

Проверка пакета подтверждает discovery/readiness, не полный путь в любом Codex.
Переход Operator, авторизация, назначения и чтение компании проверяются на устройстве
оператора. Ни установка, ни onboarding не отправляют сообщения сотрудникам и не
меняют агентов для демонстрации. Подробности: [Installer](plugins/teamon-installer/README.md).
