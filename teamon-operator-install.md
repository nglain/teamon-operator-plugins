# TeamON Operator — установка и первый вход

Получатель прикладывает этот файл в Codex и пишет «Установи».
Прочитай файл полностью и выполни шаги сам, не выдавай человеку список команд
вместо установки. Запрос разрешает установку двух указанных плагинов и каталога,
но не удаление существующих подключений, изменение агентов или обход разрешений.
Если просят только объяснить или проверить — не устанавливай.

## 1. Приветствие и подготовка экрана

Скажи: «Здравствуйте! Начинаю установку TeamON Operator — системы для управления
ИИ-сотрудниками компаний. Обычно установка занимает около двух минут. Сначала
подключу экран прогресса, затем проведу вас до входа и начала работы».
Две минуты — ориентир, не искусственная задержка и не обещание.

Сначала найди доступный `installer_open` через поиск инструментов хоста. Если
доверенный TeamON Installer уже подключён, всё равно проверь его версию и источник
через CLI ниже: наличие инструмента не подтверждает актуальность. Используй
актуальный helper, не создавай дубль. При старой версии обнови его штатно.
Bootstrap предшествует экрану: ещё не установленный MCP App
не может показывать собственную установку. Сообщи кратко «Подключаю экран»;
не утверждай, что карточка уже видна.

Проверь `node --version`, `git --version`, `codex --version` и поддерживаемый
CLI через `codex plugin --help`. Нужны macOS/Linux, Node >=24.14.1 <25, Git,
Codex с plugin-командами и поддержкой MCP Apps. Не заменяй системный Node,
не используй sudo и не отключай защиту macOS. При отсутствующей зависимости
назови конкретную проблему и один следующий шаг; не имитируй установку.

Прочитай только нужное состояние:

```sh
codex plugin marketplace list --json
codex plugin list --json
```

Официальный источник: `https://github.com/nglain/teamon-operator-plugins.git`.
Имя каталога: `teamon-operator`, рабочая ветка main без старого `--ref`.
Если каталог отсутствует:

```sh
codex plugin marketplace add https://github.com/nglain/teamon-operator-plugins.git
```

Если он уже подключён к этому источнику на main, обнови snapshot:

```sh
codex plugin marketplace upgrade teamon-operator
```

Другой источник, закреплённый ref, отключённый helper или Installer из personal —
не разрешение молча заменить настройки. Сохрани их и уточни переход на один
источник. Два одноимённых MCP одновременно не подключай.
Если helper отсутствует, установи:

```sh
codex plugin add teamon-installer@teamon-operator
```

Если он уже установлен и включён в актуальной версии каталога — пропусти add.
Если helper старый, обнови его штатной командой `codex plugin add teamon-installer@teamon-operator`
после обновления каталога. Для нового пульта нужен Installer не ниже 0.1.1 и
Operator не ниже 0.2.12. Сверяй также версию действующего MCP: установка нового
пакета не заменяет уже запущенный процесс. При старом процессе предложи
переподключить плагин и продолжи с текущего шага, без удаления входа или компании.
Проверь установленную версию/enabled через CLI. Обновление каталога само по себе
не обновляет установленный пакет. Не читай auth-файлы и не выводи значения env.

Снова найди инструменты Installer. Если они действительно не доступны после
поиска, попроси одно действие: «Выберите @TeamON Installer в этом чате и
отправьте “Продолжить установку”». Не переустанавливай здоровый пакет и не
обещай автоматическую активацию. Новый чат нужен только если текущий хост
не подхватил подключение; сохрани текущий шаг, не начинай bootstrap заново.

## 2. Живой экран и установка Operator

Вызови `installer_open` и покажи возвращённую MCP Apps-карточку внутри чата.
Это готовая бело-золотая карточка, не Visualize: не генерируй HTML, браузерную
вкладку, localhost, скриншот, таймер-имитацию или иной прогрессбар.
До запуска Operator экран должен быть открыт. После открытия скажи только:
«Нажмите “Установить Operator”. После завершения — “Начать”».

Пользователь нажимает кнопку; helper сам выполняет пять этапов. Не запускай
Operator через CLI параллельно и не вызывай app-only start вместо пользователя.
Одна карточка получает реальный статус; плавность между проверками — оценка.
100% означает проверенную установку пакета, не вход или доступ к компании.
Быстрые проверки уже установленного пакета нормальны; не растягивай их искусственно.

При ошибке читай `installer_status` точного runId. Не повторяй действие с
неизвестным исходом. Ошибка чтения ресурса — не успешный показ; сообщи её точно.
Не подменяй экран. Не удаляй пакет, cache, каталог или настройки для «починки».

## 3. После «Начать» — продолжить, не остановиться

Кнопка передаёт сообщение в чат; Codex может запросить подтверждение отправки.
Это не гарантированное @-упоминание или автоматическая активация Operator.
После получения сообщения не отвечай «тест завершён». Продолжи onboarding.
Сообщение «Помоги подключить … и войти» уже является просьбой начать вход:
не заканчивай ответ на «теперь можно войти» и не спрашивай разрешение ещё раз.

Найди инструменты TeamON Operator и вызови `installation_status` без параметров.
Если tools отсутствуют после поиска, попроси выбрать **@TeamON Operator** в этом
же чате и отправить «Помоги войти». Пакет повторно не устанавливай.
На следующем сообщении снова проверь доступные инструменты: прежнее отсутствие
не означает, что они отсутствуют сейчас. Если они появились, сразу продолжи
со статуса и входа. Не предлагай закрыть Codex или создать новый чат только
из-за задержки подключения; сначала установи конкретную ошибку подключения.

Если вход нужен, вызови `account_login_open`, передай выданную свежую ссылку.
`not_configured` и `account_login_required` ведут к этому шагу, не к повторной
установке. Если пользователь просил только установку без входа, предложи вход,
но не запускай его за пользователя. Существующую подтверждённую сессию не меняй.
Пароль вводит человек только на защищённой странице входа. Не проси пароль,
callback-код или токен в чат. Не используй заранее записанные callback URLs.
Дождись подтверждения человека; затем `installation_status(refresh_account:true)`.
Не объявляй вход успешным только потому, что ссылка открылась.

После подтверждённого входа вызови `workspace_open` и открой возвращённый URL
браузерным инструментом хоста. Это рабочий HTML-пульт с обращениями, не админка
Master и не MCP Apps. Не открывай `/admin/operators` вместо него. Если установленная
версия не предоставляет `workspace_open`, назови этот конкретный разрыв поставки;
не обещай пульт и не подменяй его старым private HTML. Не загружай чужой снимок.
Дальше пользователь выбирает компанию и агента в пульте. Для обсуждения читай
`#operator-context-data` из выбранной вкладки: явный вопрос важнее pinned, затем
browsing. Выбор не является разрешением на отправку или изменение.

Уточни нужную компанию. Полный список компаний показывай только по запросу;
по названной компании используй точный id или поиск по её названию. Не угадывай
при совпадениях. Проверь доступ только к выбранной компании. Если требуется
`instance_login_open`, проведи её отдельное браузерное подтверждение и read-back.
Ноль назначений — обратиться к администратору, не переустанавливать.
Отказ в доступе не обходить ключами, SSH или другой учётной записью.

## 4. Начало работы

Рабочее место — HTML-пульт для навигации и обычный чат Codex для обсуждения и действий.
Дай краткий гайд и предложи выбрать первую задачу:

- «Найди агента … и последний диалог с …».
- «Разбери запрос, ответ и подтверждения: что сделано, что осталось неизвестным».
- «Покажи инструкции, скиллы и коннекторы выбранного агента».
- «Подготовь ответ или изменение для моего подтверждения».

Не отправляй сообщения сотрудникам и не меняй агентов ради демонстрации.
Контекст читается по задаче, не весь флот заранее. Отправки и изменения требуют
штатного точного подтверждения и проверки результата.
В финале различи: пакет установлен, tools доступны в чате, вход проверен,
компания доступна, гайд выдан. Непроверенное так и назови.

Администратор создаёт аккаунт и назначает компании здесь:
https://master.nglain.com/admin/operators
Получателю административный доступ Master не нужен. Этот файл не выдаёт доступы
и не содержит паролей. Сохранённые входы и личные настройки не удаляются.
