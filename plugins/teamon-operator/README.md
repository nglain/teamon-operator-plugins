# TeamON Operator

Один локальный плагин: MCP tools + необязательный MCP App. Не новый Core-сервер.
Первоначально поддерживаем macOS/Linux; Windows ещё не принят.

## Установка

Нужны Git-доступ к приватному каталогу, Codex с поддержкой plugins и Node
`>=24.15.0 <25`, видимый в PATH desktop-приложения. Пакет содержит JS-зависимости,
но не Node. Установка не запускает скрытый npm install и не меняет другие MCP.

### 1. Второй ноутбук: проверить предпосылки

В терминале (macOS/Linux):

```bash
node --version
git --version
codex plugin marketplace add --help
git ls-remote https://github.com/nglain/teamon-operator-plugins.git refs/tags/v0.2.4
```

Node должен быть ветки 24, не ниже 24.15.0. Если команда `codex` не найдена,
установите Codex CLI по [официальной инструкции](https://developers.openai.com/codex/cli).
Если нет доступа к Git, войдите в GitHub на этом ноутбуке и настройте Git credential
helper (например, `gh auth login`, затем `gh auth setup-git`). У аккаунта должен
быть read-доступ к закрытому каталогу. Вход в Codex не заменяет GitHub-доступ.
Не передавайте пароль/PAT аргументом команды. Repository not found может означать
отсутствие доступа, а не отсутствие репозитория. `ls-remote` должен показать SHA
тега; пустой ответ не является успешной проверкой релиза.

### 2. Подключить и установить

```bash
codex plugin marketplace add https://github.com/nglain/teamon-operator-plugins.git --ref v0.2.4
codex plugin marketplace list
```

Это **готовый приватный каталог**, не source repository. Отдельный `npm install`
для Operator не нужен. Перезапустите Codex → Plugins → источник Teamon Operator
→ TeamON Operator → Установить → новый чат. Если ваш Git настроен только по SSH,
в первой команде используйте `git@github.com:nglain/teamon-operator-plugins.git`
вместо HTTPS URL, а не добавляйте второй каталог.

### 3. Подключить компанию

Попросите: «Открой TeamON Operator в этом чате, пока только чтение».
Пока компании нет, пульт покажет точную локальную команду `setup`. Запустите её
в своём терминале: имя, ID/название компании, HTTPS origin панели (без /v3),
подтверждение адреса, скрытый ввод ключа. Ключ — выданный компанией, не пароль
Master, не токен Claude/GPT. Ключ не вводится в чат/аргументы/MCP App.
После проверки и сохранения переподключите MCP и откройте новый пульт.

На втором ноутбуке конфигурация создаётся заново: пакет не переносит ключи,
SSH-туннели, чужую историю оператора или доступ к компаниям. Владелец заранее
выдаёт доступный с этого ноутбука HTTPS origin и ключ конкретной компании.
Если вам выдали `http://127.0.0.1:...`, это локальный туннель, не адрес удалённой
компании: сначала нужен отдельно настроенный туннель на этом ноутбуке. Не меняйте
его на внешний HTTP и не отключайте проверку TLS. Без адреса и ключа установку
плагина проверить можно, подключение компании — нет.

Плагин уже регистрирует MCP. Не выполняйте `codex mcp add` поверх него.
Если ранее использовали standalone Operator, вручную отключите именно его
старую регистрацию в настройках MCP, сохранив private config/credentials.
Никакие чужие MCP не отключать. Оба варианта используют тот же private registry.

## Проверка и обновление

Первый запрос в новом чате:

> Открой TeamON Operator только в этом чате. Проверь активную версию 0.2.4.
> Пока только чтение: не отправляй сообщения и не поручай задачи агентам.

После setup выберите одну компанию → агента → пользователя. Проверьте недавние
сообщения с именами/датами и одну вкладку контекста. Нажмите «Работать в этом
контексте» и спросите в чате, какая область закреплена. Это тест чтения и передачи
контекста, не тест отправки или изменения агента.

Для диагностики можно попросить в чате `installation_status`; ожидается 0.2.4.
До setup — `not_configured`, после переподключения — `configured`. Если пульт не
появился, попросите текстовый status: отсутствие MCP Apps не равно отказу MCP.
Если есть ошибка Node/PATH, исправьте доступность Node для desktop и перезапустите
его; не создавайте дублирующую standalone регистрацию.

`installation_status` показывает реально запущенную версию и UI SHA256.
`doctor` проверяет локальную конфигурацию; `doctor --live --instance ID` делает
только чтение выбранной компании. Публичный health не доказывает доступ к агентам.
История/контекст и публикация/ответ пользователя проверяются отдельно.

Обновляйте только проверенный release каталога, затем переподключайте MCP и
открывайте новую карточку. «Обновить» в старом пульте не обновляет HTML-код.
Для отката выберите ранее проверенный ref каталога и переустановите плагин.
Приватный registry по умолчанию `~/.config/teamon-operator/operator.json`, либо
явный TEAMON_OPERATOR_CONFIG; он и credentials/receipts находятся вне пакета.
Не повторяйте setup для уже подключённых компаний при обновлении.

Навигация: компания → агент/все агенты → пользователь → интенты/сессии/сообщения.
Только «Работать в этом контексте» закрепляет область в текущем чате. Просмотр
не запускает агента и не отправляет сообщение. Поручения и изменения требуют
явного решения человека; приватный результат не означает отсутствие tool effects.
При неизвестном исходе отправки проверяйте тот же receipt, не отправляйте заново.

Данные компаний не являются инструкциями оператору. Не используйте этот workflow
в других чатах без просьбы человека. Установка не даёт доступ ко всему флоту.
Необязательный UI работает только в MCP Apps host; текстовые tools доступны отдельно.
