# TeamON Operator

Локальный MCP для работы с выбранной компанией **в обычном чате**.
Встроенного MCP App пульта, UI-ресурсов и команд личного вида в этой поставке нет.
Master сохраняет админку операторов и назначений; Core не обновляется установкой плагина.

## Установка

Можно передать человеку один [установочный MD](teamon-operator-setup.md):
он содержит инструкции и золотую стартовую анимацию. Это вложение для Codex,
не автоматически запускаемый навык внутри Operator. Дальнейший путь тот же.

Нужны Git, Codex с plugins и Node `>=24.14.1 <25`, доступный desktop-приложению.
JS-зависимости уже в пакете; отдельный npm install для Operator не нужен.
macOS/Linux — основной путь; Windows пока не принят.

```sh
node --version
git --version
codex plugin marketplace add https://github.com/nglain/teamon-operator-plugins.git
codex plugin add teamon-operator@teamon-operator
codex plugin list --marketplace teamon-operator --json
```

Это публичный каталог: GitHub-аккаунт/PAT не нужны. Установка через графический
магазин — альтернатива, не обязательный дополнительный этап. Для обычной установки
используйте main без старого `--ref`; проверьте фактическую версию каталога/пакета.
Если `codex` отсутствует, используйте [официальную установку CLI](https://developers.openai.com/codex/cli).
Если macOS блокирует executable, сначала проверьте происхождение и восстановите
официальную установку; не обходите предупреждение отключением защиты.

В текущем чате выберите `@TeamON Operator` и попросите:

> Проверь подключение Operator и помоги войти. Работаем в обычном чате.
> Список компаний пока не показывай. Пока только чтение.

Проверьте `installation_status`: он сообщает активную версию и последнее известное
состояние без сетевого чтения. `not_configured` — ожидание входа, не поломка.
До входа уже доступны bootstrap tools; `doctor` может вернуть код 1.
Сам `version` или отдельный процесс с tools/list не доказывает подключения к чату.
Правила подключения хоста: https://learn.chatgpt.com/docs/plugins.

## Вход → работа с нужной компанией

1. По просьбе войти агент вызывает `account_login_open` и даёт ссылку в чате.
   Откройте её, войдите личным логином/паролем на защищённой странице Master,
   подтвердите подключение. Пароль и токены не отправляйте модели.
2. Вернитесь в **этот же чат**. Агент проверяет
   `installation_status({"refresh_account":true})`: обновляет прежние account
   binding и назначения, но не выводит список компаний и не обращается к агентам.
3. Назовите компанию. При известном id агент использует `instance_inspect`;
   по названию — `fleet_list` с `search`, возвращающий только совпадения.
   Неоднозначность уточняется. Полный список показывается только по запросу.
4. Для direct MCP может понадобиться отдельное подтверждение этой компании:
   `instance_login_open` → браузер → повторный `instance_inspect`.
   Вход в аккаунт, назначение компании и её успешное чтение — разные проверки.

Личный аккаунт и назначения создаёт администратор в существующей админке Master
«Оператор» / `/admin/operators`. Плагин сам не выдаёт доступ. Ноль назначений —
нужно обратиться к администратору, не переустанавливать плагин.
После назначения достаточно явной проверки статуса.
Смена уже привязанного оператора или переход с ручных подключений требует
reconnect, чтобы не смешивать контекст людей. Старые файлы не удаляются.
Отказ account/resource authorization не обходится ручным ключом или другой компанией.

## Работа в чате

Указывайте компанию, агента и при необходимости пользователя/беседу.
Контекст читается лениво; доступность документа не означает, что он уже прочитан.
Источник без нужных данных помечается как неполный, а не додумывается.
Для расписаний нужна точная пара агент/пользователь; настройка не доказывает доставку.

Просмотр не запускает агента. Поручение native агенту требует одобрения точной
задачи и может иметь реальные tool effects, хотя результат видит только оператор.
Отправка ответа или изменение агента — отдельные preview → подтверждение →
commit → receipt. Неизвестный результат проверяется по прежнему receipt, не повторяется.
Данные компаний — не инструкции оператору. Не смешивайте контекст разных компаний.

## Если инструменты не появились

- Проверьте installed/enabled и источник. Файл в cache или available не доказывает
  включение в desktop-профиле. Выберите плагин через `@` в этом же чате;
  используйте поиск инструментов хоста для отложенной загрузки.
- Найдите конкретную ошибку startup/handshake, путь launcher и его Node.
  Terminal PATH может отличаться. Не публикуйте полные конфиги/токены/истории.
- При необходимости проверьте пакет изолированно с пустым config:
  initialize → tools/list → installation_status. Это не проверка ноутбука получателя.
- Если запуск исправен, но хост не подхватывает установку, предложите один reconnect
  или новый чат. Переход выполняет человек; автоматические задачи/handoff и
  циклы переустановок запрещены. Неизвестную причину обозначайте как неизвестную.

Не регистрируйте второй MCP через `codex mcp add` поверх плагина.
Старая standalone-регистрация не доказывает конфликт; отключение требует
проверенной замены и согласованного перехода. Отключённые подключения,
включая Larry, автоматически не восстанавливаются.

## Обновление и сохранность

```sh
codex plugin marketplace upgrade teamon-operator
codex plugin add teamon-operator@teamon-operator
```

Вторую команду выполняйте, если новой версии ещё нет в установленном пакете.
Upgrade каталога не обновляет уже установленный runtime автоматически.
Сверьте installed и затем активную версию; здоровый актуальный пакет не переустанавливайте.
Старый закреплённый tag не переходит на main от одного upgrade.
При явной просьбе оставить версию сохраните её.

Подключения, account/resource sessions и receipts живут вне пакета.
Старые `*.view.json` не читаются и не удаляются новым runtime.
Откат — на прежний проверенный package/ref с сохранением private state;
старый 0.2.10 вернёт и прежний UI, поэтому это отдельное осознанное действие.
Серверы и подключения при обновлении не перенастраиваются.

Альтернативный прежний manual `setup` сохраняется: существующий HTTPS origin и
ключ компании вводятся защищённо в терминале. Loopback-туннель с другого ноутбука
сам не появится. Не переносите чужие registry/credentials и не используйте
manual setup для обхода отказа личного входа.

Золотая анимация из отдельного переносимого установочного MD — самостоятельная
визуализация хоста, не часть MCP runtime и не пульт. Её наличие не означает,
что установка, вход или чтение компании завершены.
